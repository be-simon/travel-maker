# Map View (F5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add F5 (지도 뷰) to the 플랜 screen: a 타임라인⇄지도 toggle, spot markers distinguishing candidate (grey) from confirmed (colored) status with a priority highlight, 날짜/도시/카테고리 filters, a marker-click detail card with a "일정에 추가" action, numbered route-sequencing for a selected date, and Google Places search integrated into 장소 추가 so newly-created spots actually carry coordinates for the map to plot.

**Architecture:** `@vis.gl/react-google-maps` (Google's official React wrapper, confirmed React 19-compatible) wraps the Maps JavaScript API. A `MapProvider` component gates everything on `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` being set, rendering a clear Korean fallback message when it isn't. `MapView` sits alongside the existing `TimelineView` (from the M2 plan) behind a new client-side toggle (`PlanCanvas`), sharing the same `spots`/`blocks` data already fetched by `plan/page.tsx`. Legacy `google.maps.Marker` (via the library's `<Marker>` wrapper) is used instead of `AdvancedMarkerElement`, specifically to avoid the separate "Map ID" Cloud Console setup step that advanced markers require — this keeps the external-dependency list to just the one API key already scaffolded in `.env.example`.

**Tech Stack:** Adds `@vis.gl/react-google-maps` (v1.9.0 confirmed current, React 19-compatible) and `@types/google.maps` (as an explicit devDependency, not relying on transitive hoisting) to the existing Next.js 16 + TypeScript + Supabase stack.

  - Do not write code that "would probably work" from general Google Maps familiarity. Every task below gives you the exact, verified-current API shape (verified against the npm registry, GitHub source, and official docs as of 2026-08 — not older tutorials, which likely show deprecated patterns). Follow it precisely.
  - The Definition of Done at the bottom of this plan explicitly does NOT include "confirmed working with a real map" — that verification happens later, by the project owner, once they have a key. Don't let that gap block you from completing and committing correct, well-reasoned code.
- **Critical, easy-to-get-wrong pattern — apply it in every task that touches `google.maps.*` constants (icons, symbols, `SymbolPath`, etc.):** these globals do not exist until the Maps JavaScript SDK has finished loading. A component that references `google.maps.SymbolPath.CIRCLE` (or similar) directly in its own render body — even as a child of `<APIProvider>`/`<Map>` — can throw `ReferenceError: google is not defined` if it renders before the script loads, because prop values are evaluated by the *parent's* render function, not gated by the child component it's passed to. The library's own components (`<Marker>`, `<Polyline>`) internally no-op safely until ready, but *your* code computing a `google.maps.Symbol` object to pass as a prop is not automatically protected. **The safe pattern: isolate any code that references `google.maps.*` constants inside a small child component that calls `useMap()` first and returns `null` if it's `null`** (confirmed hook, used internally by the library's own `<Polyline>`). Only once `useMap()` returns a real `google.maps.Map` instance is it safe to reference `google.maps.*` globals. Every task below that needs this follows this pattern — do not simplify it away.
- Never instantiate a Supabase client ad hoc. Every Server Action follows the established convention: `{ error: string | null }`, `console.error(...)` + generic Korean fallback on Supabase error, never `error.message` verbatim.
- The `spots` table already has `place_id`, `lat`, `lng`, `address` columns (from M1's initial schema — designed up front, unused until now). **No new migration is needed anywhere in this plan.**
- Do not modify `src/app/trips/[tripId]/plan/timeline-view.tsx` except where a task explicitly says to (only Task 4 touches it, and only to add one optional field to `BlockDraft` in the co-located `block-dialog.tsx` — `timeline-view.tsx` itself is untouched by this whole plan).
- **Scope cuts, deliberate — do not treat their absence as a gap:**
  - Editing/deleting a spot's location after creation is out of scope (matches M2's "spot edit/delete out of scope" cut).
  - Clustering markers when many spots are close together is out of scope — not called for by the PRD at this trip scale, and adds a real dependency (`@googlemaps/markerclusterer`) for a problem that won't manifest with a handful of trip spots.
  - Drawing the *driving/walking* route between sequenced spots (as opposed to a straight connecting line) is out of scope — the PRD explicitly separates this ("실제 도보 경로 기반 정확한 이동시간" is an Open Question, not P0); the polyline here is a straight-line visual aid only, same spirit as the M2 plan's already-deferred travel-time hints.
  - Reverse-geocoding a manually-entered spot (one created without using Places search) to backfill coordinates is out of scope. A spot without coordinates simply doesn't appear on the map — the panel/timeline are unaffected.
  - Mobile-responsive map layout is out of scope (matches M2's mobile cut).

- [ ] **Step 1: Write `src/app/trips/[tripId]/plan/map-view.tsx`**

```tsx
'use client'

import { Map, Marker, useMap } from '@vis.gl/react-google-maps'
import type { PlanBlock, Spot } from '@/types/database'
import { MapProvider } from '@/components/map/map-provider'

// 좌표가 있는 스팟이 하나도 없을 때(빈 트립)의 기본 중심점 — 서울시청.
const DEFAULT_CENTER = { lat: 37.5665, lng: 126.978 }

interface LocatedSpot extends Spot {
  lat: number
  lng: number
}

function isLocated(spot: Spot): spot is LocatedSpot {
  return spot.lat !== null && spot.lng !== null
}

// google.maps.* 상수(SymbolPath 등)는 지도 SDK 로드가 끝나기 전까지 존재하지
// 않는다. useMap()이 null을 반환하는 동안(로드 전)에는 아무것도 렌더링하지
// 않고, 실제 지도 인스턴스가 생긴 뒤에만(=SDK가 로드된 뒤에만) 마커를 그려서
// "google is not defined" 런타임 에러를 피한다.
function SpotMarkers({ spots }: { spots: LocatedSpot[] }) {
  const map = useMap()
  if (!map) return null

  return (
    <>
      {spots.map((spot) => {
        const isConfirmed = spot.status !== 'candidate'
        return (
          <Marker
            key={spot.id}
            position={{ lat: spot.lat, lng: spot.lng }}
            icon={{
              path: google.maps.SymbolPath.CIRCLE,
              scale: spot.priority ? 11 : 8,
              fillColor: isConfirmed ? '#2563eb' : '#9ca3af',
              fillOpacity: 1,
              strokeColor: '#ffffff',
              strokeWeight: spot.priority ? 3 : 2,
            }}
          />
        )
      })}
    </>
  )
}

export function MapView({
  spots,
}: {
  tripId: number
  startDate: string
  endDate: string
  blocks: PlanBlock[]
  spots: Spot[]
}) {
  const located = spots.filter(isLocated)
  const center = located.length > 0 ? { lat: located[0].lat, lng: located[0].lng } : DEFAULT_CENTER

  return (
    <MapProvider>
      <div className="h-[600px] w-full overflow-hidden rounded-lg border">
        <Map
          defaultCenter={center}
          defaultZoom={located.length > 0 ? 12 : 10}
          gestureHandling="greedy"
          mapId={undefined}
        >
          <SpotMarkers spots={located} />
        </Map>
      </div>
      {spots.length > 0 && located.length === 0 && (
        <p className="mt-2 text-sm text-muted-foreground">
          좌표가 있는 장소가 없습니다. 장소를 추가할 때 검색 결과에서 선택하면 지도에 표시됩니다.
        </p>
      )}
    </MapProvider>
  )
}
```

(`mapId={undefined}` is explicit and intentional — omitting a Map ID is what keeps this on the legacy `Marker`/`Symbol` styling path rather than requiring `AdvancedMarkerElement`, per this plan's Architecture section.)

```ts
import { describe, it, expect } from 'vitest'

// Mirrors map-view.tsx's spotIdsScheduledOnDate — kept in sync manually since
// it's not exported (small, private helper). If this drifts from the real
// implementation, that's a signal to export it properly; for now this proves
// the *intended* semantics independent of the Google Maps-dependent component.
function spotIdsScheduledOnDate(
  blocks: { date: string; type: string; spot_id: number | null }[],
  date: string
): Set<number> {
  const ids = new Set<number>()
  for (const block of blocks) {
    if (block.date === date && block.type === 'spot' && block.spot_id !== null) {
      ids.add(block.spot_id)
    }
  }
  return ids
}

describe('spotIdsScheduledOnDate', () => {
  it('only includes spot-type blocks on the exact date with a linked spot', () => {
    const blocks = [
      { date: '2026-06-01', type: 'spot', spot_id: 1 },
      { date: '2026-06-01', type: 'transport', spot_id: null },
      { date: '2026-06-02', type: 'spot', spot_id: 2 },
      { date: '2026-06-01', type: 'spot', spot_id: null },
    ]
    expect(spotIdsScheduledOnDate(blocks, '2026-06-01')).toEqual(new Set([1]))
  })

  it('returns an empty set for a date with no matching blocks', () => {
```

```ts
function buildRouteForDate(blocks: PlanBlock[], spots: LocatedSpot[], date: string): RouteStop[] {
  const spotById = new Map(spots.map((spot) => [spot.id, spot]))
  return blocks
    .filter((block) => block.date === date && block.type === 'spot' && block.spot_id !== null)
    .sort((a, b) => a.start_time.localeCompare(b.start_time))
    .map((block) => spotById.get(block.spot_id!))
    .filter((spot): spot is LocatedSpot => spot !== undefined)
    .map((spot, index) => ({ spot, sequence: index + 1 }))
}
```

This is Google's own official reference implementation (from the `@vis.gl/react-google-maps` repo's `examples/autocomplete`), used verbatim:

```ts
'use client'

import { useEffect, useRef, useState } from 'react'
import { useMapsLibrary } from '@vis.gl/react-google-maps'

export interface UseAutocompleteSuggestionsReturn {
  suggestions: google.maps.places.AutocompleteSuggestion[]
  isLoading: boolean
  resetSession: () => void
}

export function useAutocompleteSuggestions(
  inputString: string,
  requestOptions: Partial<google.maps.places.AutocompleteRequest> = {}
): UseAutocompleteSuggestionsReturn {
  const placesLib = useMapsLibrary('places')
  const sessionTokenRef = useRef<google.maps.places.AutocompleteSessionToken | null>(null)
  const [suggestions, setSuggestions] = useState<google.maps.places.AutocompleteSuggestion[]>([])
  const [isLoading, setIsLoading] = useState(false)

  useEffect(() => {
    if (!placesLib) return
    const { AutocompleteSessionToken, AutocompleteSuggestion } = placesLib

    if (!sessionTokenRef.current) {
      sessionTokenRef.current = new AutocompleteSessionToken()
    }

    if (inputString === '') {
      setSuggestions([])
      return
    }

    const request: google.maps.places.AutocompleteRequest = {
      ...requestOptions,
      input: inputString,
      sessionToken: sessionTokenRef.current,
    }

    setIsLoading(true)
    AutocompleteSuggestion.fetchAutocompleteSuggestions(request).then((res) => {
      setSuggestions(res.suggestions)
      setIsLoading(false)
    })
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [placesLib, inputString])

  return {
    suggestions,
    isLoading,
    resetSession: () => {
      sessionTokenRef.current = null
      setSuggestions([])
    },
  }
}
```

(The `eslint-disable` on the effect's dependency array matches the official example exactly — it intentionally omits `requestOptions`, which would otherwise be a new object reference on every render and cause an infinite fetch loop; this project doesn't pass `requestOptions` from its only call site in Step 2 below, so this is inert in practice but kept for fidelity to the verified source.)
